# FHIR Care Copilot v0.2.1 CodeQL Security Hardening Design

Date: 2026-08-04
Status: approved
Target release: `v0.2.1`
Baseline: `main` at `18e28a02c040672e503cbab14f864131f6c4da3a`
Working branch: `codex/codeql-hardening-v0.2.1`

## 1. Objective

Ship one narrowly scoped security patch that resolves the real issues found by GitHub CodeQL,
records technically defensible false-positive dispositions, and preserves the frozen portfolio
application's behavior and public evidence. The patch must improve credential handling, reduce
patient-identifying log content, and explicitly restrict GitHub Actions token permissions without
adding product features or changing the architecture.

The project remains a security-focused AI application demonstrated with Synthea synthetic data.
This patch does not make it a clinical product and must not be described as proof of clinical
safety, diagnostic value, treatment quality, or production authorization readiness.

## 2. Evidence and finding classification

GitHub CodeQL default setup completed successfully on 2026-08-04 for GitHub Actions,
JavaScript/TypeScript, and Python. The initial scan reported 18 open alerts: 14 high severity and
4 medium severity. Those alerts map to four actionable root causes and three false-positive root
causes.

## 4. Browser credential design

`app/src/api.ts` will replace the storage-backed key with one module-private string. `setApiKey`
updates that string, `getApiKey` returns it, and the existing request function adds `X-API-Key`
only when the string is non-empty. The key is therefore available only to the current loaded page
and is lost on refresh, navigation that reloads the application, tab close, or process exit.

The implementation must not read an API key from `localStorage` or `sessionStorage`, and must
never write one there. To remove residue created by `v0.2.0`, initialization may perform a
best-effort `removeItem` for the single legacy key name without reading or copying its value. A
storage-access failure must remain non-fatal. No cookie, IndexedDB, URL, build-time environment
variable, or alternate persistence mechanism will be introduced.

`app/src/components/StatusBar.tsx` will receive a copy-only correction with no markup hierarchy,
layout, styling, or interaction redesign. The text must state that the key is held in the current
page's memory, is sent to this service with API requests, and is cleared by refresh or page close.
It must not imply that a browser-held key is inaccessible to same-page scripts or that this demo
implements production-grade authentication.

Focused frontend tests will prove that:

- `setApiKey` and `getApiKey` round-trip only through module memory.
- clearing the key removes it from subsequent request headers.
- a simulated module/page reload loses the key.
- the legacy storage key is removed without reading its value, and unavailable storage does not
  break module initialization.
- no key is written to `localStorage` or `sessionStorage`.
- an in-memory key still produces the existing `X-API-Key` header.
- the StatusBar disclosure describes memory-only, current-page lifetime.

## 5. Log minimization design

### Generic local FHIR store

`src/fhir_copilot/store/local.py` will keep the current deterministic behavior of retaining the
first bundle for a duplicate patient ID. Only the warning payload changes: it becomes a constant
message that contains neither the patient ID nor the source filename. A focused `caplog` test in
`tests/test_local_store.py` will create synthetic sentinel values, confirm the warning occurs, and
assert that neither sentinel appears in captured logs.

### Synthea acquisition verification

`scripts/download_or_generate_synthea.py` will keep its verification step but report only the
aggregate patient count. It will no longer enumerate sample IDs, names, gender, or birth dates.
A focused test will use synthetic test bundles, execute the verification path, and assert that the
aggregate count is present while all sentinel record fields are absent from logs.

### Malformed direct-secret diagnostics

`scripts/publish_to_hf.py` will reject malformed `--set-secret` input without interpolating the
raw input into its diagnostic. The message will state the required `NAME=VALUE` format or that the
secret name must be non-empty. A main-path regression will use only synthetic sentinels for missing
`=` and empty-name inputs, assert exit status 1, and prove that neither sentinel nor raw input is
captured in logs.

These changes reduce unnecessary disclosure even though the repository's public dataset is
synthetic. They do not relabel synthetic resources as real patient records, and passing the tests
does not establish clinical privacy compliance.

## 6. GitHub Actions permission design

`.github/workflows/ci.yml` will declare the following at workflow scope:

```yaml
permissions:
  contents: read
```

No job receives write permission. No new workflow, trigger, retry, action, service, or release
automation is added. A parsed-YAML contract test will assert the exact top-level permission so the
setting cannot silently regress. The existing CI matrix, Docker build/smoke, and other jobs remain
otherwise unchanged.

## 7. False-positive disposition

The nine false-positive alerts remain open until all of the following are true:

1. The implementation diff has been reviewed line by line.
2. Local focused tests and the full CPU-safe suite pass.
3. GitHub CI and CodeQL complete successfully for the release candidate.
4. The exact alert locations are re-opened and verified to log only names/identifiers of
   configuration fields, never their values.
5. The final `main` CodeQL scan is complete at the exact release SHA.

Each alert will then be dismissed individually as `false positive` with a technical note tied to
its data flow. The notes will distinguish a configuration **name** from its secret **value** and
will not claim that all logging is risk-free. Actionable alerts must close through code changes,
not dismissal. Autofix will not be used. If any reviewed flow can contain a value, dismissal stops
and the release returns to the implementation stage for a minimal fix.

Suggested disposition language:

- Provider/configuration-name diagnostic: “The sink receives a fixed provider or environment
  variable name used for diagnostics; the environment variable value is never read into this log
  argument.”
- API-key configuration-name diagnostic: “The sink receives the constant name
  `FHIR_COPILOT_API_KEYS`; configured key entries and request credentials are not logged.”
- Hugging Face publication diagnostics: “The sink reports allowlisted secret/variable names or a
  missing-name condition; the publisher does not retrieve or print the corresponding secret
  value.”

## 9. Implementation and publication sequence

The patch uses stop gates so that a failed external system cannot be converted into an unrelated
repository change:

1. Implement in `codex/codeql-hardening-v0.2.1` using test-first changes for credential and log
   behavior, followed by the workflow permission and release metadata updates.
2. Run focused tests after each change, then the complete backend, frontend, formatting/lint,
   type-check, release-contract, and CPU-safe suites.
3. Build the repository Docker image, run the container in mock/synthetic mode, wait for healthy,
   call the host health endpoint, execute the existing minimum API smoke, and clean up the
   container.
4. Push only the patch branch and wait for its GitHub CI and CodeQL results. A failure stops the
   flow; there is no automatic retry loop or opportunistic feature work.
5. Publish the exact clean release-candidate tree to the existing Hugging Face Space through the
   repository's allowlisted publisher, with mock provider, Synthea data, and CPU hardware. Verify
   build state, health, mock model identity, demo mode, patient count, patient list, summary, and
   one no-cost chat request. Do not read or print secret values.
6. Fast-forward `main` only after the branch and public mock candidate pass. Push without force,
   then wait for exact-SHA GitHub CI and CodeQL.
7. Verify and dismiss only the nine proven false positives. Confirm no actionable alert remains.
8. Create an annotated `v0.2.1` tag and GitHub patch Release at the exact verified `main` SHA.
   Do not attach or record a new demo video.
9. Confirm remote/default `main`, tag, Release target, HF revision contents, local `main`, and all
   evidence surfaces agree; confirm GitHub Contributors still lists only `kuotunyu`.

No tag, Release, alert dismissal, main integration, or Hugging Face mutation occurs during design
or implementation review.

## 10. Verification and acceptance criteria

The candidate is acceptable only when all of the following are evidenced:

- No browser code reads or persists an API key through Web Storage; the legacy key is only
  best-effort deleted, never read.
- Refresh/module reload clears the active key, while an active in-memory key still authorizes
  existing requests through `X-API-Key`.
- UI copy accurately explains current-page memory lifetime and request transmission.
- Duplicate-patient logs contain neither patient ID nor source filename.
- Synthea verification logs contain an aggregate count and no record-level identifier or
  demographic sentinel.
- CI declares only `contents: read` at workflow scope and all existing jobs still pass.
- Package, runtime, lockfile, citation, and release-contract versions agree on `0.2.1`; the lockfile
  has no dependency drift other than the exact `postcss` `8.5.22` to `8.5.23` transitive security
  patch. The patch must pass `npm ci`, resolve only `postcss@8.5.23`, clear the moderate-or-higher
  npm audit gate, and preserve frontend lint, full Vitest, and build compatibility.
- Full backend/frontend tests, lint/format checks, type checks, Docker build, health, and minimum
  API smoke pass on CPU with mock/synthetic settings.
- Branch and final-main CodeQL scans complete for Actions, JavaScript/TypeScript, and Python.
- The four actionable roots are closed by code. The nine dismissed alerts have individual,
  technically accurate false-positive notes, and no unresolved high/medium actionable alert
  remains.
- The exact clean candidate is what CI scans, HF serves, `main` references, and `v0.2.1` tags.
- HF remains `provider=mock`, `model_id=mock-deterministic`, `demo_mode=true`, synthetic-only, and
  CPU-hosted; no paid API or GPU is used.
- Documentation and release notes retain the explicit synthetic-data and non-clinical-use
  boundary and do not turn test success into a clinical-readiness claim.
- Commit author/committer, tagger, and GitHub Contributors remain exclusively `kuotunyu`; no bot
  or AI co-author is added.
- Every local worktree is clean and no verification container remains running at closeout.

## 11. Failure containment and rollback

- Any unexpected change to `origin/main`, dirty worktree, contributor identity, version-bearing
  artifact, or public deployment stops integration.
- Any test, Docker, CI, CodeQL, or HF failure is classified before action. External registry or
  runner failures are reported and are not converted into repository fixes.
- No force push, rebase, squash, amend, tag replacement, Release deletion, or history rewrite is
  allowed.
- Before main integration, a code defect is corrected only on the patch branch with the smallest
  test-backed change. After publication, any additional correction requires separate approval and
  a new patch version; `v0.2.1` is not moved.
- If HF publication fails, keep the previous known-good revision available and do not enable a
  paid provider as fallback.
- If an alleged false positive proves capable of carrying a value, do not dismiss it. Return to a
  minimal code fix and repeat the full candidate verification.

## 12. Definition of done

`v0.2.1` is done when the four actionable CodeQL roots are fixed, the nine false positives are
individually justified, all local/Docker/GitHub/HF evidence points to one exact commit, and the
public project remains an honest mock/synthetic, non-clinical AI/backend portfolio application.
At that point the repository returns to feature freeze; no additional feature work is implied by
this patch.
