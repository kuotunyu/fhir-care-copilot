# ADR 0002：Python 3.11 → 3.13（Windows 中文路徑的 cp950 編碼問題）

- **狀態**：Accepted
- **日期**:2026-07-19
- **取代**:原規劃的 Python 3.11(PLAN.md 初版、原始需求 spec)

## 背景

M0 建骨架時實測發現:專案路徑含中文(`CC_github部隊\長照\`),`uv sync` 建出的
editable install 會產生 `.venv/Lib/site-packages/_editable_impl_fhir_copilot.pth`,
內容是 **UTF-8 編碼**的專案路徑。

Python 3.11/3.12 的 `site` 模組讀 `.pth` 檔時固定用 `encoding="locale"`
(zh-TW Windows 上是 **cp950**),**即使設了 `PYTHONUTF8=1` 也不會改變**
(UTF-8 mode 不影響 `encoding="locale"` 的行為)。結果 venv 的 Python 啟動即炸:

```
Fatal Python error: init_import_site: Failed to import the site module
UnicodeDecodeError: 'cp950' codec can't decode byte 0xe9 in position 31
```

(`0xe9 83 a8` 正是「部」的 UTF-8 bytes。)

## 決策

**改用 Python 3.13**(`requires-python = ">=3.13"`、`.python-version = 3.13`)。
CPython 3.13 起 `.pth` 檔改為**優先以 UTF-8 解碼**(fallback locale),問題根除。
已實測:3.13 下 `uv sync` + `pytest/ruff/mypy/pre-commit` 全綠。

原始 spec 指定 3.11,但同一份 spec 也要求「若任何套件 API 已更新,優先依官方文件
調整,不要鎖死過時版本」——3.13 為穩定版本,所有相依套件均支援,符合精神。

## 考慮過的替代方案

| 方案 | 否決原因 |
|---|---|
| `PYTHONUTF8=1` | 實測無效(`encoding="locale"` 不受 UTF-8 mode 影響) |
| `uv sync --no-editable` | 每次改碼要重裝,開發體驗差 |
| 搬到純 ASCII 路徑 | 動使用者的專案組織方式,留作最後手段 |
| Windows「Beta: UTF-8 全域」設定 | 影響整台機器所有程式,風險過大 |

## 連帶影響

- `.pre-commit-config.yaml` 必須保持 **ASCII-only**:pre-commit 以系統 locale 編碼
  讀自己的設定檔,中文註解會炸(實測,已修)。其他會被工具以 locale 編碼讀取的
  設定檔比照辦理。
- Python 原始碼內的中文 docstring/註解安全(PEP 263,`.py` 預設 UTF-8)。
- 之後 M4(node/vite)與 M7(docker build)在中文路徑上仍需實測,結果記入 PROGRESS。
